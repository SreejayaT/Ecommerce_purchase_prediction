An imbalanced signal

Why this is harder than it looks

Across the dataset, roughly 1 in 6.5 sessions results in a purchase. A model that always predicts “no purchase” is already about 85% accurate, and completely useless for a marketing team trying to find the shoppers worth targeting.

The real objective isn’t accuracy. It’s the trade-off between precision and recall on the minority purchase class. Every model below uses class weighting, and each one’s decision threshold is chosen on a validation set rather than on the final test set.

The pipeline

Load to locked threshold

01

Stratified train / validation / test split

The purchase rate holds at about 15.5% in every split, so the minority class is represented consistently.

train 7,891 → validation 1,973 → untouched test 2,466
02

Preprocess, fitted on training data only

Numeric features are median-imputed and standardised. The seven categorical columns are one-hot encoded, giving 75 model inputs. Every step is fitted on the training split and only applied to validation and test.

03

Three candidate models

Logistic Regression as a transparent baseline, Random Forest for non-linear interactions, XGBoost for gradient-boosted performance.

04

Weight the minority class

Logistic Regression and Random Forest use class_weight="balanced". XGBoost gets an explicit scale_pos_weight computed from the training class ratio.

05

Choose thresholds on validation, then lock them

Each model’s cutoff is the one that maximises F1 on the validation set. It is fixed before the test set is scored, so no test label influences it.

Random Forest and XGBoost are effectively tied. XGBoost’s ROC-AUC lead is 0.002 and Random Forest’s F1 lead is 0.022, both small enough that a single split with 382 test purchases could reverse them. Both clearly beat the Logistic Regression baseline.

Validation-selected cutoffs

Chosen before the final test

A probability becomes a class label only after a decision threshold is applied. The three models produce differently calibrated probabilities, so each gets its own cutoff, picked to maximise F1 on the validation set.

Validation F1 runs a little above test F1 for every model (0.657 vs 0.616, 0.694 vs 0.666, 0.701 vs 0.644). That gap is the expected optimism of choosing a cutoff on the data it is scored on, which is why the test figures are the ones to quote. ROC-AUC does not depend on a threshold.

What this enables

From model to action

Target the right sessions

Score live sessions in real time and route the highest-probability visitors into retention offers or exit-intent prompts before they leave.

Explainable baseline

Logistic Regression’s coefficients give a transparent starting point for stakeholders who need to trust the “why,” not just the score.

Tunable for the business

The threshold isn’t fixed — a campaign with a bigger budget can lower it for more reach; a tighter one can raise it for precision.
