An imbalanced signal

Why this is harder than it looks

Across the dataset, roughly 1 in 6.5 sessions results in a purchase. A model that always predicts “no purchase” is already 84% accurate — and completely useless for a marketing team trying to find the shoppers worth targeting.

The real objective isn’t accuracy. It’s the trade-off between precision and recall on the minority purchase class. Every model below uses class weighting and a decision threshold selected independently on the validation set, rather than tuning the threshold on the final test set.

The pipeline

Load to tuned threshold

01

Stratified train / validation / test split

The data are separated into training, validation, and final test sets. Stratification preserves the purchase-rate balance across splits.

train → validation → untouched test
02

Fit preprocessing on training data

Preprocessing is fitted using the training data and then applied consistently to validation and test data, preventing information from the held-out test set from influencing model development.

03

Three candidate models

Logistic Regression as a transparent baseline, Random Forest for non-linear interactions, XGBoost for gradient-boosted performance — each carrying its own way of handling the class imbalance.

04

Weight the minority class

Logistic Regression and Random Forest use class_weight="balanced"; XGBoost is given an explicit scale_pos_weight computed from the train-set class ratio.

05

Select thresholds on validation data

Each model's predicted probabilities are evaluated on the validation set. The threshold that gives the chosen operating point is selected there, then locked before the final test evaluation.

Validation-selected cutoffs

Thresholds chosen before the final test

A probability becomes a class label only after applying a decision threshold. Because the three models produce differently calibrated probability distributions, the notebook selects the operating threshold independently for each model using the validation set.

0.50LR
0.35RF
0.5768XGB

These thresholds are selected using validation data and then locked. The final precision, recall, F1 and confusion matrices are calculated on the untouched test set. ROC-AUC remains threshold-independent because it uses the continuous prediction probabilities.

What this enables

From model to action

Target the right sessions

Score live sessions in real time and route the highest-probability visitors into retention offers or exit-intent prompts before they leave.

Explainable baseline

Logistic Regression’s coefficients give a transparent starting point for stakeholders who need to trust the “why,” not just the score.

Tunable for the business

The threshold is a model-specific operating point selected during validation. It can be revisited for a different business objective, but any new threshold should be selected without using the final test set.
